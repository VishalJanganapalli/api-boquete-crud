BOUQUET CRUD API - ENDPOINTS, PAYLOADS & REQUIRED FIELDS
========================================================
Base URL (local):  http://localhost:3000
Base URL (Render): https://api-boquete-crud.onrender.com

The API uses the separate MongoDB database "bouquets_db" and the
"bouquets" collection. MongoDB creates the database and collection when
the API first writes data. On first startup, the API inserts 20 starter
bouquets only when the collection is empty. Restarting the API will not
duplicate or overwrite existing data. The existing products database
is not changed.

--------------------------------------------------------
1. HEALTH CHECK AND SUMMARY
--------------------------------------------------------
GET /api/health
GET /api/bouquets/meta/summary

Health returns the API and MongoDB connection status.
Summary returns totalBouquets, category names, and unitsAvailable.

--------------------------------------------------------
2. GET ALL BOUQUETS / FILTER
--------------------------------------------------------
GET /api/bouquets
Header: Accept: application/json
Body: none

All matching bouquets are returned directly; there is no pagination.

Supported query filters:
?search=rose
?category=Roses
?occasion=Birthday
?color=Pink
?size=Large
?minPrice=20&maxPrice=80
?inStock=true
?stockStatus=IN_STOCK
?stockStatus=LOW_STOCK
?stockStatus=OUT_OF_STOCK
?tags=romantic,roses
?isFeatured=true
?isNewArrival=true
?isOnSale=true
?hasFreeDelivery=true
?sortBy=price&order=asc

sortBy supports: price, name, createdAt, stockQuantity
order supports: asc, desc
IN_STOCK means more than 5 items; LOW_STOCK means 1 to 5;
OUT_OF_STOCK means 0. Filters can be combined.

Examples:
GET /api/bouquets?category=Roses&minPrice=30&isFeatured=true
GET /api/bouquets?search=spring&inStock=true&sortBy=price&order=asc

--------------------------------------------------------
3. GET ONE BOUQUET
--------------------------------------------------------
GET /api/bouquets/:id
Example: GET /api/bouquets/665123456789012345678901
Header: Accept: application/json
Body: none

--------------------------------------------------------
4. CREATE A BOUQUET
--------------------------------------------------------
POST /api/bouquets
Header: Content-Type: application/json

Required fields:
  name          String
  sku           String (unique)
  description   String
  price         Number greater than 0
  category      String
  flowers       Array of at least one flower name
  color         String
  size          Small, Medium, Large, or Premium
  stockQuantity Integer, 0 or greater
  thumbnail     String (image URL)

Example minimal payload:
{
  "name": "Spring Rose Bouquet",
  "sku": "BQT-021",
  "description": "Fresh pink roses with seasonal greenery.",
  "price": 45.99,
  "category": "Roses",
  "flowers": ["Pink Rose", "Eucalyptus"],
  "color": "Pink",
  "size": "Medium",
  "stockQuantity": 12,
  "thumbnail": "https://example.com/spring-rose.jpg"
}

Optional fields:
  shortDescription (String, default "")
  compareAtPrice (Number or null, default null)
  discountPercentage (calculated automatically when compareAtPrice > price)
  occasion (String, default "")
  images (Array of strings, default [])
  tags (Array of strings, default [])
  isFeatured (Boolean, default false)
  isNewArrival (Boolean, default false)
  isOnSale (Boolean; automatically true when compareAtPrice > price)
  hasFreeDelivery (Boolean, default false)
  status (active, draft, archived; default active)
  createdAt and updatedAt (automatically managed)

--------------------------------------------------------
5. REPLACE A BOUQUET (PUT)
--------------------------------------------------------
PUT /api/bouquets/:id
Header: Content-Type: application/json

PUT replaces the bouquet. Send all required fields. Optional fields not
sent are replaced with their defaults.

Send the complete required payload (same as CREATE API)

--------------------------------------------------------
6. PARTIALLY UPDATE A BOUQUET (PATCH)
--------------------------------------------------------
PATCH /api/bouquets/:id
Header: Content-Type: application/json

Send only fields to change. Example:
{
  "price": 39.99,
  "isFeatured": true,
  "stockQuantity": 8
}

--------------------------------------------------------
7. DELETE A BOUQUET
--------------------------------------------------------
DELETE /api/bouquets/:id
Header: Accept: application/json
Body: none




=======================================
STUDENT PRACTICE QUESTIONS
=======================================

Use the Bouquet API base URL at the top of this document. Build a page
that displays bouquets as cards. Each card should show the bouquet name,
price, image, category, and stock status.

1. DISPLAY ALL BOUQUETS
   Which GET request returns all bouquets? Display the returned items in
   a responsive card grid. Use images[0] when available, otherwise use
   thumbnail.

2. COMBINE FILTERS
   Can you combine search, category, and price filters in one request?
   Add a "Clear filters" button that removes all selected filters and
   fetches the full list again.

3. SORT RESULTS
   Add a sort selector for price (low to high and high to low), name, or
   stock quantity. Which sortBy and order values does the API accept?

4. CONDITIONAL PRODUCT CHIPS
   Use conditional statements to show the following chips on each card:
   - If isFeatured is true, show "Featured".
   - If isNewArrival is true, show "New".
   - If isOnSale is true, show "Sale".
   - If hasFreeDelivery is true, show "Free Delivery".
   - If stockQuantity is 0, show "Out of Stock".
   - If stockQuantity is from 1 to 5, show "Low Stock".
   - If stockQuantity is greater than 5, show "In Stock".
   What should the card look like when a bouquet has several chips?

5. CONDITIONAL PRICE DISPLAY
   If compareAtPrice is greater than price, show compareAtPrice with a
   strike-through, show the current price, and display discountPercentage.
   Otherwise, show only the current price.

6. CONDITIONAL ACTIONS
   Should the "Add to Cart" button be enabled when stockQuantity is 0?
   Implement the button state using a condition and display an
   appropriate message to the customer.

7. LOADING, EMPTY, AND ERROR STATES
    What should the page show while the GET request is loading? What
    should it show when no bouquets match the filters? How should it
    report an API or network error, and how can the student retry?

8. CREATE AND EDIT
    Create a form that sends POST /api/bouquets. Which fields are
    required? Then add an edit form that sends PUT with all required
    fields, and a quick-update control that sends PATCH with only the
    changed field(s). Show validation errors from the API.

9. DELETE
    Add a delete button that sends DELETE /api/bouquets/:id. Ask for
    confirmation before deleting, show the result, and refresh the list.
